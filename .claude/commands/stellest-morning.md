아침루틴: 오늘 Daily sales report 메일에서 파일을 받고, Stellest 지표를 계산해 Notion 「일일 실적 요약」에 저장한 뒤 결론을 보고한다. 처음부터 끝까지 한 번에 진행하고, 아래 "멈추고 물어볼 때"에 해당할 때만 나에게 묻는다.

## 0. 준비 확인
- Chrome에서 Outlook(https://outlook.cloud.microsoft/mail/)에 로그인되어 있는지 확인한다. 안 되어 있으면 "Outlook 로그인 필요"라고 알리고 멈춘다.
- 오늘 날짜와 요일을 확인한다. 주말·공휴일(일요일, 아래 공휴일 목록)이면 메일이 없으니 "오늘은 메일이 오지 않는 날"이라고 알리고 멈춘다.

## 1. 파일 받기
1. Outlook 검색창에 `from:PARKJE subject:"Daily sales report"` 를 입력하고 Enter. 맨 위(가장 최근) 메일을 연다.
2. 제목 형식은 "Daily sales report ( October-13 )"이고, 제목의 날짜가 데이터 기준일이다. 메일은 보통 다음 영업일 오전 10:30~10:50경 도착한다.
   - 기대하는 기준일 = 오늘 직전 영업일(영업일: 일요일·공휴일 제외, 토요일은 포함). 단 월요일 아침 메일은 토요일(일요일 수주 포함) 기준일 수 있다.
   - 가장 최근 메일의 기준일이 기대 기준일보다 오래됐으면 "아직 오늘 메일 미도착"이라고 알리고 멈춘다.
3. 첨부 xlsx 2개를 각각 "기타 작업 > 다운로드"로 받는다 ("모두 다운로드" 금지).
   - Daily Order InTake Report _YYYY_MM(공유용).xlsx (약 19MB) = 데일리 오더
   - Daily Sales Report_YYYY_MM(공유용).xlsx (약 5MB) = 데일리 세일즈
4. %USERPROFILE%\Downloads 에 받은 파일 두 개를 %USERPROFILE%\Documents\Stellest_Daily\YYYY-MM-DD\ (YYYY-MM-DD = 데이터 기준일)로 옮긴다. 폴더가 없으면 만든다. 파일명은 그대로 둔다.
5. 같은 폴더에 같은 이름의 파일이 이미 있으면 같은 파일인지(크기·수정시간) 확인한다. 같으면 다시 받지 않고 기존 파일을 쓴다. 다르면 덮어쓰기 전에 나에게 묻는다.
6. 파일 크기가 위 용량과 비슷한지 확인한다.

## 2. Stellest 지표 계산 (나는 Stellest 매니저이므로 Stellest 수량만 본다)
- 세일즈 파일: `STELLEST` 시트(Simple Name = STELLEST)의 총합계가 MTD 순매출(인보이스 - 반품)이다. 고객별 행의 합이 총합계와 맞는지 검증한다.
- 오더 파일: `세부내역` 시트에서 Simple Name = STELLEST, Month = 기준일의 월(예: 10월)로 거른다. 주문 수량은 이 행들의 수량 합이다.
- 오더링 어카운트: 위 오더 행에서 Ordering Customer Code의 중복을 제거한 수. 수량 0 이하 행은 제외한다. (참고로 취소·종료 상태까지 빼면 수가 줄어드는데, 확정치는 "수량 0 이하만 제외" 기준이다.)
- 월 목표(2026, pcs, 인보이스·순매출 기준): 1월 3,240 / 2월 4,320 / 3월 4,860 / 4월 4,320 / 5월 4,860 / 6월 3,780 / 7월 4,320 / 8월 5,400 / 9월 5,400 / 10월 4,320 / 11월 4,320 / 12월 4,860 (연간 54,000). 달성률은 반드시 세일즈 파일 수량(순매출)으로 계산하고 주문 수량과 비교하지 않는다. SIS 대시보드 월별 상세 표(https://claude.ai/artifact/Vurr6Aavqh6ht8U48W35yM)와 다르면 SIS 값을 따르고 알려 준다.
- 달성률 = MTD 순매출 / 월 목표. 잔여 수량 = 월 목표 - MTD 순매출.
- 월말 마감 예상 = MTD 순매출 / 경과 영업일 x 해당 월 영업일. 영업일은 일요일·공휴일을 제외하고 토요일은 포함한다 (SIS와 같은 기준, 토요일 출고분이 MTD에 들어 있다). 계산 근거 수식을 함께 적는다.
- 공휴일(평일): 2026-10-03 개천절, 10-05 대체공휴일, 10-09 한글날, 12-25 성탄절, 2027-01-01 신정. 이 목록에 없는 날이 공휴일일 수 있으면 확인해서 알려 준다.
- 기간 표기는 YTD / MTD / 1Q·2Q·3Q·4Q를 쓰고, 보고는 공식적인 톤, 결론 먼저, 근거 나중으로 쓴다.

## 3. 저장
1. 기준일 폴더에 summary.csv를 저장한다 (같은 이름이 있으면 덮어쓰기 전에 묻는다). 컬럼:
   date,stellest_sales_pcs_mtd,monthly_target_pcs,achievement_rate,remaining_pcs,projected_month_end_pcs,stellest_order_pcs_mtd,ordering_accounts_mtd
2. Notion 「일일 실적 요약」 데이터베이스(https://app.notion.com/p/6163aefcfbde4b159615e719c380e2e9, data source collection://39eaf0a5-f9d8-42e6-8d08-b2d410c4b880)에 기준일 한 줄을 저장한다.
   - 먼저 같은 기준일 행이 있는지 조회한다. 조회는 반드시 **보기(view) 모드**로 한다: 도구 notion-query-data-sources에 mode="view", view_url="https://app.notion.com/p/6163aefcfbde4b159615e719c380e2e9?v=3fa095a3-bd59-81da-a795-000ca00cbf49"를 넘긴다 (기준일 내림차순 보기). SQL·rows 모드는 Notion 사용량 한도에 걸릴 수 있으니 쓰지 않는다.
   - 같은 기준일 행이 있으면 그 행을 갱신하고, 없으면 새 행을 추가한다 (중복 행 금지, 삭제 금지). 조회가 한도 때문에 실패하면 notion-fetch로 데이터베이스를 열어 확인하거나, 확인이 안 되면 새 행을 추가하지 말고 나에게 묻는다.
   - 속성: 이름 = "YYYY-MM-DD Stellest MTD", 기준일 = 데이터 기준일(날짜), MTD 순매출, 월 목표, 달성률 (0.2905처럼 비율), 잔여 수량, 월말 예상, 주문 수량, 오더링 어카운트 (모두 숫자), 메모 = 특이사항 한 줄.
   - 출근 대시보드(https://claude.ai/artifact/7VqUbbsUgP3rkLxX2WBHx8)가 이 표의 가장 최근 기준일 행을 읽는다. 원본 xlsx 내용은 Notion에 올리지 않고 위 요약 숫자만 올린다.

## 4. 보고 (결론 먼저)
- 한 문장 결론: 기준일, MTD 순매출, 월 목표 대비 달성률, 경과 영업일 비율과의 차이, 월말 예상과 목표 대비 비율.
- 표: MTD 순매출 / 월 목표 / 달성률 / 잔여 수량 / 월말 예상 / 오더링 어카운트(전일 대비 증감) / 주문 수량(참고용, 목표와 직접 비교하지 않음).
- 근거: 필터한 시트·컬럼, 영업일 수(경과/전체), 검증 결과.
- 확인이 필요한 사항: 전일 대비 순증이 0이거나 이상한 값, 기준일이 기대 기준일과 다른 경우 등.
- 마지막 줄에 "출근 대시보드에 반영됨 (Notion 일일 실적 요약)" 또는 반영 실패 사유.

## 멈추고 물어볼 때
- Outlook 로그인이 안 되어 있거나 오늘 메일이 아직 없을 때
- 같은 이름의 파일이 다르게 존재해 덮어써야 할 때
- 시트 이름이나 컬럼이 위 설명과 달라 필터를 확정할 수 없을 때 (이때는 시트·컬럼 목록과 샘플 3행을 보여 준다)
- 계산 결과가 직전 기록과 크게 어긋날 때 (예: 달성률이 줄었거나 MTD가 직전보다 작을 때)

## 절대 규칙
- 파일과 Notion 행을 삭제하지 않는다. 메일을 보내거나 답장하지 않는다.
- 숫자를 추정해서 채우지 않는다. 계산할 수 없는 값은 비워 두고 이유를 적는다.
